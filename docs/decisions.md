# Decisions

One line per decision, with its reason.

- **Nx targets inferred from `package.json` scripts** instead of Nx generators and executors: fewer moving parts, each package stays runnable with plain npm, Nx still adds caching, the project graph and `affected`.
- **Libraries consumed from source** (`exports` points to `src/index.ts`): Vite and Vitest compile TS directly, so there is no library build step to keep in sync.
- **TypeScript 6.0** rather than 7.0: `typescript-eslint` supports TS up to 6.0 today; upgrade when it supports 7.
- **ESLint 10 flat config at the root**, shared by every package; Prettier handles formatting (`eslint-config-prettier` turns off conflicting rules).
- **npm `overrides` for `undici`**: Nx pulls a version with known advisories; pinning the patched minor keeps `npm audit` clean without forcing installs.
- **`libs/core` has no `DOM` lib in its tsconfig**: the compiler guarantees the business logic never touches the browser.
- **Money in integer cents** with a single `quoteStay` function: totals never pick up floating point errors and every screen shows the same numbers.
- **Promo codes are looked up, never parsed**: the URL value is only a key into the code list, so `?promo=100` cannot become a 100 % discount.
- **`validateBooking` in the core** returns every blocking issue; `createBooking` reuses it, so the UI and the booking itself can never disagree.
- **Storage behind a `StorageLike` interface** in the core: the core stays DOM-free and the "storage blocked" path is unit-tested.
- **Lit without decorators** (`static properties` + `declare` fields): no extra compiler settings, works with the standard `useDefineForClassFields` behaviour.
- **Typed `var()` references (`vars`) from the tokens package**: components interpolate `t.color.primary` in their CSS, so a misspelt token fails to compile instead of silently falling back.
- **One custom event name per payload type** (`tb-input`, `tb-date-change`, `tb-count-change`, `tb-select`): each can be declared once in `HTMLElementEventMap` with an exact `detail` type.
- **Events bubble and are `composed`**: they cross shadow roots, like native UI events, so any framework can listen on the host element.
- **No `<form>` around the `tb-*` fields**: inputs inside shadow roots are not form-associated; the app reads values from events instead. Form-associated custom elements (`ElementInternals`) are a possible future upgrade.
- **Native `<input type="date">`** inside `tb-date-field`: accessible picker, keyboard support and localisation without a date library.
- **React app has no router**: the confirmation is a view state; a router adds nothing for two screens.
- **React JSX types in `custom-elements.ts` (not `.d.ts`)**: with `skipLibCheck`, mistakes in a `.d.ts` file are silently ignored.
- **Room photos as 16:10 WebP in two sizes** (`name.webp` at 640 px, `name@2x.webp` at 1280 px, picked by `srcset`): realistic images that show what each stay is like, about 35 KB per card on standard screens and sharp on high-density ones. Created for Tidebook, so they show fictional places with no licensing questions.
- **Netlify `ignore` with `git diff`** rather than the `nx-ignore` package: no extra install on every deploy and the rule is readable in one line; the trade-off is listing the watched paths by hand (`apps/<app>`, `libs`, root workspace files). Switch to `nx-ignore` if the dependency graph grows beyond what one line can describe.
- **E2E in its own project** with `implicitDependencies` on the apps: `nx affected` runs it whenever the app or any library it uses changes, and the app's Netlify build does not watch it.
- **E2E runs against the production build** (`vite preview`), the same files Netlify serves, in a desktop and a mobile (Pixel 7) Chromium project. Other browsers can be added as projects when needed.
- **E2E locators by role and label only**: Playwright pierces open shadow roots, so the tests read like a user's actions and double as an accessibility check on the `tb-*` components.
- **Shared app assets live in the libraries**: the page layout stylesheet (`@tidebook/ui/layout.css`) and the room photos and favicon (`libs/ui/public`, used as Vite's `publicDir`) are in `libs/ui`; the user-facing booking messages and `formatLongDate` are in `libs/core`. Every app shows the same page from one source, and a change there is picked up by Nx caching and `nx affected`.
- **Vue app with `<script setup>` SFCs and Composition API** (`ref`, `computed`): the current recommended Vue style, and the closest match to the React app's hooks for a fair comparison.
- **`tb-*` typed in Vue through `GlobalComponents`**, checked by `vue-tsc`: listeners are typed as `onTbSelect`-style props because that is how Vue compiles `@tb-select`.
- **`vue/attribute-hyphenation` ignores `tb-*` tags**: their bindings are property names (`pricePerNight`), which Vue sets directly on the element.
- **One E2E project (`apps/e2e`) for every app**: the same tests run against each production build on desktop and mobile, so the apps cannot drift apart. It replaces `apps/react-e2e`.
- **Storybook inside `libs/ui`** rather than a separate app: stories sit next to the components they document, and Nx gives the library `storybook` and `build-storybook` targets. Stories and `.storybook/` are excluded from the `production` input, so editing a story never rebuilds or redeploys the apps.
- **Stories written with Lit `html`** and typed `Args` picked from each component class: controls match the real properties, and `fn()` logs the typed `tb-*` events in the Actions panel.
- **Docs and accessibility addons only**, telemetry disabled: autodocs pages for every component and an axe check on each story, without extra weight.
- **Storybook has its own Netlify site** (`libs/ui/netlify.toml`) that only rebuilds when `libs/ui`, `libs/tokens` or the workspace setup change.
- **Angular 22 with standalone components, signals and zoneless change detection**: the current defaults of the framework, and the closest match to Vue's `ref`/`computed` for a fair comparison.
- **`CUSTOM_ELEMENTS_SCHEMA` and no extra typings in Angular**: with `strictTemplates`, Angular already types `(tb-select)` events from the `HTMLElementEventMap` entries in `libs/ui`. Property bindings on `tb-*` are not type-checked under the schema; the E2E suite covers them.
- **Angular copies `libs/ui/public` before `dev` and `build`** (npm `pre` scripts, git-ignored `apps/angular/public`): the Angular builder only serves assets inside its own folder, and a one-line Node copy works on every OS, unlike a symlink.
- **Angular unit tests with the official Vitest runner** (`@angular/build:unit-test`): the same test runner as the rest of the monorepo.
- **Angular linted with the shared ESLint config only**: templates are already checked at build time by `strictTemplates`; `angular-eslint` can be added if template style rules become useful.
- **Removed the `:not(:defined)` hiding rule from the layout CSS**: every app registers the `tb-*` elements before its first render, so it never helped, and it hid Angular's `<app-root>`, which is not a registered custom element.
- **Node 22.22.3 or later**: the minimum required by Angular 22; Netlify builds with the latest Node 22.
- **One E2E suite for three apps**: React, Vue and Angular run the same 3 scenarios on desktop and mobile (18 runs).
